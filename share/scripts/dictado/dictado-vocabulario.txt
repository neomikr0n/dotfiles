# LA GRAFÍA SÍ SE CORRIGE
# La escribió de memoria y traía erratas que NO se pueden dejar: "Hyperland" (la marca es
# Hyprland), "Pipewire" (es PipeWire) y "Gamescope" (es gamescope, en minúscula). Dejarlas tal

# También se unificó "RME" + "ADI-2" + "DAC" en "RME ADI-2 DAC", que contiene las tres, y se

# "RADEON" VA PRIMERO, Y ES A PROPÓSITO

# escribe "a E.O." y con "Radeon" en el prompt escribe "Radeon". Lo que está delante en la lista
# pesa más, así que va la primera para darle la mejor posición posible.
#
# EL LÍMITE NO ES UNA CUOTA, ES UN ÓPTIMO (medido el 2026-10-10)
# Lo que importa no es cuántos caracteres caben, sino cuáles. Medido sobre el corpus completo
# (12 frases, 89.54 s, 216 palabras, voz de n30, whisper large-v3-turbo, dos pasadas idénticas),
# con el WER y la normalización del banco del proyecto, dictado-bench.py:
#
#   324 car.  lista base                        15 errores   6.9 %
#   363 car.  base + las 3 unidades             16 errores   7.4 %
#   444 car.  base + las 10 de abajo            12 errores   5.6 %   <- el mejor medido
#   583 car.  base + 24 palabras                17 errores   7.9 %
#   sin lista                                   22 errores  10.2 %
#
# La curva NO es monótona: añadir palabras no mejora por acumulación, y un subconjunto de lo que
# ayuda aquí (solo las 3 unidades) empeora. Llenar hasta el tope de 600 EMPEORA respecto a esta
# lista, y además vuelve a romper los nombres propios: con las 24 palabras, m3-propios pasó de 0
# a 4 errores. La causa es que las palabras genéricas diluyen el sesgo hacia los nombres propios,
# que es lo único que este prompt aporta de verdad. Esta lista ocupa 444 caracteres, que es el
# óptimo medido, no el máximo que cabe.
#
# CÓMO SE EDITA
